# 项目额外指标和统计

下列内容来自项目自己的开发集诊断或运行报告，不进入官方 `evaluation.py` 的评分；这里是清单，不代表用户已决定保留。具体统计口径、去重和待核事项以对应报告为准。

| 名称 | 想衡量什么 | 单位和主要限制 |
|---|---|---|
| USR（更新成功） | 更新后是否完整、正确地保存目标核心新状态 | 以人工选定的主目标计；部分覆盖按严格口径不算成功；语义判定仍需复核。 |
| KPR（知识保留） | 更新前已保存且应保留的事实，更新后是否仍完整保留 | 用户 × 会话 × 合格具体事实；事实拆分、有效性、去重和待核项会改变分母。 |
| JSR（联合成功） | 同一目标的更新成功，同时其合格保护事实均保留 | 可按目标或会话计；保护范围和未知项影响结果，两种单位不能混加。 |
| JSR 敏感性统计 | 比较目标自身保护候选与同会话候选并集的影响 | 是 JSR 的另一保护集合口径，不能与主口径相加。 |
| 诊断分类 | 旧命题未入库、召回不足、应改未改、越界修改、有效知识损伤、证据不足 | 用于定位原因，属于待人工审查标签，不是官方评分。 |
| 核心完整／部分／未保存、保护候选定位与损伤计数 | 展示开发目标及保护候选的诊断过程 | 候选行不等于去重后事实数；定位到片段不代表完整保留。 |
| 运行观察 | 候选、检索、空检索、失败、解析失败、复核数量、模型调用量、token 和耗时 | 用于追踪覆盖与成本，不能替代质量指标；旧报告对 all/valid 分母按其已记录输入单独聚合。 |
| Mem0 操作统计 | ADD、UPDATE、DELETE、NONE 的计划和实际执行情况 | 反映操作和异常，不自动说明语义更新正确。 |

`all` 和 `valid` 本身**不是本项目新增指标**：官方 `evaluation.py` 已分别计算对应口径。旧的项目报告自行实现了更新和 QA 的分类汇总，并增加了失败追踪；在不完整输入等情况下，其 `all` 资格定义可能不同于官方 CLI，不能直接等同。
