# ScopePlan：离线规划与回放

## 状态与输入边界

`plan.build_plan(request, relation_result, annotations=None)` 输出 `modify / preserve / uncertain / add` 四类**待审核候选**和原样 `upstream_original`；不执行记忆写入。每项均有旧事实 `(memory_id, fact_index)`、旧引文、新证据引文、属性、条件和理由。无法确定的属性/条件显式为 `null`/`unknown`，不会由人工验收预期填充。上游失败时仅附请求中的原始新证据，不信任失败候选。

两组共用完全相同的 `build_plan`：

1. **structured**：组件一输入与原始基线结果，加上一轮依据人工审核整理的结构化范围候选。人工审核确认的是目标事实和允许边界，**不是每个结构化字段均被用户独立确认**；手工周三例和其 mock 本身为构造数据。结构化来源仅校验引用及旧新侧，不自动证明属性语义。
2. **baseline_only**：只将已保存组件一基线及其原始请求传给规划器；不注入 `old_units`、`new_unit`、人工结论或预期。周三没有真实基线，使用本地模拟 backend 经过原 v2 `judge` 得到结果。引文实验不参与这两组。

输出均为候选，`hold_provisional` 是缺依据时暂停变更和保留原文，**不声称旧状态一直有效**。`add` 的 `raw_evidence_candidate` 仅保留原始新引文，并未证明它是新事实、原子命题或可去重写入。用户请求的语义历史化在证据门槛不满足时会被明确搁置，不能将保守输出计作目标变化已完成。

## 决策和范围

- 只允许 `historical_correction`、人工提供的 `explicit_verified` 纠正标注（须有与上游新引用对齐的原文来源）、完整确定的交集、可在上游片段中唯一定位且有旧记忆引文支持的属性，共同满足时，产生 `modify` 候选。`explicit_verified` 是调用方对语义的外部确认，不是本程序由逐字匹配得出的判断。
- `possible_change`、`support`、标签外或无可用上游、未知边界、缺失属性定位均不触发修改。`support` 没有时间和状态连续性的独立证明，不能据此断言没有阶段变化。
- 对完整交集，使用日期闭区间和星期集合从旧范围计算差集：其他星期、受影响星期在交集之前及之后的片段分别保留；端点按相邻日推导。若交集只证明一个子集或边界未知，不伪造完整差集。
- 如修改的旧文本片段与保护片段及其时间／星期范围可能相交，或保护片段无法定位，则撤回修改并加入 `protection_overlap` 待确认。跨子事实也执行该检查；多个修改片段和范围可能重叠时转为 `modification_overlap` 待确认。修改项的旧引文必须覆盖其实际片段；无结构化旧范围则返回 `old_scope_missing`。多子事实的结构化旧范围必须明确标出 `fact_index`，未标注不向任一子事实猜测分配。
- 此实现按日期精度处理，不涵盖跨时区/小时、复杂规则例外、同义共指自动判断或原子化事实抽取。`compare` 的部分交集证明保守且不完备。

## 三案两组结果

各项的完整旧／新引文、适用条件、理由、原始输出见 [two-group results](scope_plan_runs/three_cases.json)。下表的「新增」均指原始引文候选；「暂存」均指 `hold_provisional`。

| 案例 | 组 | modify | preserve | uncertain | add 与缺失 |
|---|---|---|---|---|---|
| 晋升 | structured | 无 | 雇主对应属性保留；职称暂存 | `possible_change`；职称有效边界未知 | 晋升原文候选；准确生效时间未知，历史化尚未生成 |
| 晋升 | baseline_only | 无 | 整条旧引文暂存 | 整句候选覆盖职称与雇主，无法可靠限定属性；`possible_change`，边界未知 | 晋升原文候选；组件一的 `position` 自由文本不能独立证明局部 span |
| 周三（手工） | structured | 无 | 2026-01-01 起周一；2026-01-01 至 2026-11-30 的周三 | 2026-12-01 起的周三是确定相交范围，但关系仍为 `possible_change` | 新办公安排原文候选；尚无经过确认的明确纠正，因此不改 |
| 周三（手工） | baseline_only | 无 | 整条旧引文暂存 | `possible_change`；未注入结构化星期、日期或属性，边界和属性待定位 | 新办公安排原文候选；虽原文含日期，本组没有可靠结构化解析结果 |
| 转岗 | structured | 无 | 旧转岗进度暂存 | `support` 无法证明同一阶段持续；有效边界未知 | 已转岗原文候选；准确转岗日、今后求职状态未知，尚未生成历史化 |
| 转岗 | baseline_only | 无 | 整条旧引文暂存 | `support` 不授权修改；属性与有效边界均未定位 | 已转岗原文候选；没有将 2026-03-01 记录时间当生效日 |

明确纠正的正向计算由单独的手工控制测试验证：修改 `work from home` 在指定日期起的周三，保留周一和变更日前周三；该控制例不是这三个真实／模拟组件一输出的新结果。

[独立预期](cases/scope_plan_expectations.json)只由 [评分程序](score_plan.py) 在规划后读取。[评分结果](scope_plan_runs/score.json)中 **30/30 是预设的安全门槛和覆盖检查**，不是语义准确率。三案目标变化均未生成 `modify`：前两条真实案例及模拟例的目标变化仍待补足明确关系或边界，不能把 30/30 写成三案历史化完成。

## 扩展开发子集

[完整逐项输出](scope_plan_runs/development.json)覆盖原人工确认的五案与配对实验中全部 18 个已保存 v2 子事实输入，共 **23 个子事实行、21 个审核目标**；是按已有两组产物选取的开发回放，不是全部 24 条审核行，也不是独立盲测。没有以人工审核结论填充基线输入。

- **21/23 行**通过上游校验并产生保守候选（覆盖 20 个目标）；这不是 21 个确定范围规划成功。其余 **2/23 行**的上游旧片段未找到（第 5、23 条各一行），只保留原输入证据并报 `upstream_error`。
- 21 个可进入规划的行全部有 `attribute_unlocalized` 和 `boundary_unknown`；其中 9 行 `possible_change`、8 行 `support_not_change`、4 行其他非纠正关系。所有 23 行均无确定修改候选；**0 行完成由基线证据支持的确定修改范围规划**。
- 5 行输入没有覆盖其人工审核目标的全部证据：职业历史案以及配对记录 3、17、18、21。它们的结果仅对应实际输入，不能把缺少的信息计作模型遗漏；其余的来源覆盖初筛也不是语义正确性保证。
- 人工审核共 24 行，其中 19 个接受／修订接受主目标；这里的 21 个目标还包括重复确认对照，不能与 19 个主目标直接相加。配对报告另将一条拆分语义不合格项排除、一条归并且未单独运行；与晋升同会话的一项未纳入该组。未知其他产物是否另有相应可用基线，不能把本范围外情况称为全部无法处理。

## 重放和验证

在本目录运行（不调用模型）：

```bash
python plan_replay.py three > scope_plan_runs/three_cases.json
python plan_replay.py development > scope_plan_runs/development.json
python score_plan.py > scope_plan_runs/score.json
python -m unittest discover -s . -p 'test_*.py' -v
```

原有 `replay.py` 与范围交集样例仍保留。组件一和 Mem0 写入层没有修改。
