# 组件一受控对照计划

目标：在不变更 v2、拆分器、组件二和 Mem0 的前提下，以既有五个原始请求比较 v2 与独立改进提示词。

设计：保留既有六标签、严格字段和 v2 验证。阶段发生实质进展时优先 possible_change；证据同时支持并补充时，若无既有标签能完整表达，使用 uncertain 表示分类表达不足，reason 分别给出支持与新增并说明保留旧事实，问题仅确认如何表示两部分。与对象关系等事实未知分开说明。替代方案：扩展 candidate 增加辅助字段会被组件二严格校验拒绝；将混合关系直接标 support/supplement 与当前标签定义冲突。代价：uncertain 在下游是待复核，无法机器读取第二关系。

步骤：
1. 新建模块，复用 v2 judge 和校验，只新增提示词。对合法候选、无效引文和无重试运行契约验证。
2. 五个输入直接取已有组件二运行的 request，原样冻结；同一模型实例、同一 backend、相同 Qwen3-8B BF16/cuda、贪心、768 tokens，无自动重试，保存逐次原始请求、提示词、响应和指标。
3. 汇总五例事实边界与输出，标注未盲标与语义未验证，分析组件二和上游限制。
4. 运行组件一和组件二现有单测，核查输入一致、次数、截断和历史文件不变。
