## 提示词、示例、数据和校验器一致性

- 变化证据：提示文字要求与新引文同来源、为其连续子串，校验器实际要求每项为含 `source_id`、`quote` 的对象；JSON 示例却仅给 `change_evidence: []`，没有给非空对象示例。四处模型输出字符串；该格式确实不满足现有校验器，但示例没有完整展示所需形态。
- `object`：示例用字面字符串 `"...或 null"` 表示两种可能，补充文字才说明要使用 JSON `null`。校验器接受非空字符串或 null，因此不会识别误用该占位字符串。五案未报告这一格式失误。
- 覆盖：提示词允许复合单元拆多条，校验器只检查 ID 是否出现或列入 unmatched，不能判断每个断言是否拆出，也可能将有 ID 但缺正确引用的单元计为已覆盖。Susan 的 Daniel 主张、职业历史 `unsplit-new-2`、以及转岗中不同断言说明只看 ID 不够。
- 引用：提示词和校验器均要求每个关联单元有属于其 `memory_quotes` 的对应侧引文。Susan `ctx-1` 虽是相关上下文，却不是两个旧单元的来源；跳伞多关联的 `new-0`、`new-2` 和 `u3` 在对应记录缺引文。
- 限定词：提示词要求其属于同侧关联来源并修饰正确主张，校验器只检查种类枚举及同侧关联来源中含有原文；它允许来源上下文中、单元短引文外的限定词，也无法验证作用对象或语义类型。Susan 把整段朋友记忆标成 `negation`，来源检查却通过；跳伞把模拟绑定到安全承诺，来源也不属于关联单元，因而被检出。五案还有未提取或未绑定的限定词，空数组在结构层可通过。
- `state_change` 要有旧单元和新变化依据；时间词不可换算日期。校验器检查日期格式与原文存在，不负责判断变化、因果或限定关系是否成立。v2 所有 `event_date` 为 null，不能说明相对时间完整。

## 逐案语义与来源追踪

1. **Susan**：前两条将支持和鼓励归给 Susan，未将 Daniel 的行为写进 Susan 的主张，但两条引文都包含 Daniel，Daniel 的独立行为遗漏。旧正文明确 `ThomasSusan (referred to as 'Susan')`，所以旧记忆提供别名依据；新话语中的支持并不独立明说新的“朋友关系”，首条 `support` 仍需人工判断。第三条凭空生成“现职支持福祉”的旧主张，却把朋友记忆标为否定；新句的实际否定是“当前工作对福祉的支持不及期望”，不是完全没有支持。`lately` 修饰近期思考职业，非自动修饰求职目标；寻找更好平衡且符合人道目标的新工作的意向被漏掉。
2. **晋升**：职位变化有 `got promoted to lead director` 的直接新证据；公司持续关系有对应原文。`recently` 修饰晋升，未绑定。变化引文本身在新引用中，但格式错误使校验无法验证。
3. **职业历史**：两条不再把新公司获客定为旧雇主或旧职位的状态变化；但 `new_claim` 第一条写 `user runs ...`，第二条写 `founder/operator`，说明也将其扩大为创业者／负责人。输入 `manually_mapped_new` 的 `raw_statement`、`memory_quotes` 和人工 `attribute.value=client_milestone` 只表明“我的咨询公司终于获得初始客户”，没有创始人或经营者身份；因此这次扩大来自 v2 生成，并非选中的上游单元已含该身份。所有上下文只能用于指代，不能把其他未选单元的用户句或助手推断当作本记录依据。选中句的 `lately` 修饰感到宽慰，`finally` 修饰获客；后者是前者陈述的原因。v2 漏掉 `unsplit-new-2`，因此漏掉两人关系及维护关系的内容；政治咨询出现在上下文，但不在所引的选中句中，不能由所引句单独证明。
4. **转岗**：句子直接陈述已转到新岗位，以及工作生活平衡如今好得多；v2 合并两项断言，`now` 未绑定平衡主张。原求职计划与已转岗可表示进展，但“直接矛盾”把前后阶段混同；不应据此推断不会再找其他工作。
5. **跳伞**：v2 保留 `simulated skydiving`，没有把模拟体验当作真实极限运动偏好变化，这是改善；“模拟风险特征不同／模拟不冲突”未被所引用户文本直接证明。`still prioritize safety` 支持安全重视程度，并不足以单独支持旧的“高受伤风险是厌恶理由”；将其标为该具体风险理由的 `support` 扩大了依据。模拟限定属于新体验，不属于 `new-8` 的独立安全承诺；`For now` 限定目前享受刺激／观察其发展，不能机械绑定后句安全优先。`didn't expect` 修饰预期，并非否定实际享受；`recently` 关联模拟体验。v2 未结构化这些时间和否定表达。

## 下一版的离线约束

以单元 ID、属性、关系、两侧逐字片段为主体；附着在具体侧和具体引用主张上的限定词按需保留。来源 ID 从已关联单元与片段映射；只有唯一来源时补全并记录，多来源时输出候选和歧义，不选一个冒充确定值。应分别列出未处理单元、缺失依据、结构错误及人工语义意见；即使引文逐字且来源正确，也不能自动声称其语义蕴含、限定词作用范围或复合单元的断言覆盖正确。

## 对 v2 字符串证据的来源候选离线检查

按“原字符串须位于原 `new_quotes` 且该引用必须属于所关联新单元”的条件，仅做来源候选定位，不修改原始响应或 v2 结构结论：晋升 `records[1]` 唯一对应 `new-0`，转岗 `records[0]` 唯一对应 `new-0`，跳伞 `records[1]`、`records[2]` 各唯一对应 `new-8`。四项结果及逐字字符串记录在 `diagnosis.json` 的 `change_evidence_source_candidates` 中。唯一来源只能修补来源标识的可定位性；跳伞的安全引用仍不足以证明高受伤风险理由，不能把来源定位成功当成语义修复。v3 将不再单独生成重复的 `change_evidence`，而以记录的新原文作为待审核依据。
