# v1/v2 五案配对回放

这是基于 v1 已见错误调整提示词后的开发回放，语义结论为助手对原文和两版原始响应的逐项审核，并非独立盲测或用户确认的金标准。v2 每案一次，**5 次请求、5 次响应、0 自动重试**，均为 `qwen-plus-2025-12-01`、温度 0、JSON 输出。

每案保存了与 v1 的完整输入、旧单元、新单元、来源文本及 user 消息字节的 SHA-256；五案均相等。原始输入、提示词、返回、解析、错误和 token 用量在各案 JSON 中，运行时提示词及代码另保存在 `frozen_code/`。本轮没有重写模型响应。

## 结构检查

| 案例 | v1 | v2 | v2 主要错误 |
|---|---|---|---|
| Susan | failed，3 项 | failed，3 项 | 新增记录用旧上下文引文关联两个旧单元，引用未落在两单元的 `memory_quotes`。 |
| 晋升 | passed | failed，2 项 | `change_evidence` 用字符串而非包含来源 ID 和引文的对象；因此不能完成来源校验。 |
| 职业历史 | passed | failed，1 项 | 新单元 `unsplit-new-2` 完全未被处理。 |
| 转岗 | passed | failed，2 项 | `change_evidence` 用字符串，缺来源 ID。 |
| 跳伞 | failed，6 项 | failed，8 项 | 部分关联单元缺对应引文；安全记录的模拟限定词来自未关联的新单元；两处 `change_evidence` 为字符串。 |

五案均解析出 JSON；v2 旧单元 ID 均被提及，职业历史漏掉一个新单元，其他案例的新单元 ID 均被提及。ID 被提及不等于该单元的全部主张或语义被正确处理。v2 的输出 schema 和检查比 v1 增加了主张、限定词及变化证据字段，因此两版结构通过数不能当作相同校验器下的直接质量分数。

## 语义逐项对照

| 案例／检查项 | v1 | v2 实际结果 | 修复情况与新错误 |

| Susan：人物与支持 | Susan 的新主张合并了 Daniel 的内容。 | 两条 Susan `new_claim` 只写 Susan／ThomasSusan 的支持，但两条新引文仍包含 Daniel 句子，且没有单列 Daniel 的主张。 | **部分修复**：未再把 Daniel 行为写进 Susan 的主张；人物证据仍未分开处理。 |
| Susan：旧朋友关系 | 有 Susan 支持证据，但旧引用超出 `friendship` 单元。 | 首条旧引文改为 `friend named ThomasSusan`；新主张写成“与 Susan 有朋友关系”。 | **部分修复**：首条引用范围修正；新引文明确说支持与鼓励，并未独立明说朋友关系。后续一条又出现新的旧引用归属错误。 |
| Susan：求职和限定 | 求职 `plan` 存在，但 `lately` 字段类型错误。 | 仅表达当前工作不足以支持福祉，未表达寻找新工作的意向；没有对应的 `lately` 或否定限定词。 | **未修复**：原来的时间字段格式错误不再出现，但该计划和限定词被遗漏。**新错误**：凭空写旧主张“current role supports well-being”，并把整段旧朋友记忆错误标为否定限定词。 |
| 晋升：职位和公司 | 正确识别已升为 lead director，公司未变，并记录 `recently`。 | 仍将职位标为 `state_change`、公司标为 `support`；变化证据文本为 `got promoted to lead director`。 | **原正确结论保持**；**新错误**：变化证据缺来源 ID、结构不合要求，且 `recently` 未绑定到新主张的限定词。 |
| 职业历史：旧雇主、旧职位 | 把获客推成雇主和职位的 `state_change`。 | 两条均改为 `new_information`，关系说明称新证据没有否定或替换旧雇主、旧职位。 | **修复该标签错误**：没有再将获客直接标成旧雇主／职位的状态变化。 |
| 职业历史：本人身份与获客 | 无依据地写 `founder/owner of consulting firm`；获客另列新增。 | 仍写 `founder/operator` 和 `user runs a consulting firm`；获客只被嵌在含未经证实经营身份的主张中。 | **未修复**：`my consulting firm finally secured some initial clients` 不足以单独证明创始人、所有者或经营者身份；应单独表达获客并将身份留作未知。 |
| 职业历史：两人关系和时间 | 单列 MooreSandra、GonzalezMary 的人脉作用；错误把 `lately` 附到获客等主张。 | 整个 `unsplit-new-2` 未覆盖；也未表达“最近感到宽慰”，限定词为空。 | **部分修复**：未再错误绑定 `lately`，但相应感受／时间被遗漏。**新错误**：两人关系单元漏判；关系说明还引入选定新引文未表明的政治咨询领域。 |
| 转岗：完成与平衡 | 识别已转岗，但新主张未单独表达平衡改善，未提取 `now`。 | 新主张包含 `finally transitioned` 和 `much healthier now`，类型为 `state_change`。 | **部分修复**：已表达完成转岗和平衡改善；`now` 仍未作为新主张限定词绑定。**新错误**：`target_relation` 写 `different`，变化引文只给字符串；说明中“直接矛盾”容易混淆前后阶段。 |
| 跳伞：模拟与真实态度 | 把模拟体验标成真实极限运动偏好的 `state_change`。 | 新对象写 `simulated skydiving`，模拟限定挂在该体验上，类型改为 `supplement`；说明明确不能据此推翻真实态度。 | **修复该错误**：保留模拟与真实活动的区分。说明中的“风险特征不同”并非本案用户引文直接给出，仍需保留不确定。 |
| 跳伞：受伤风险理由 | 将风险理由标为 `state_change`。 | 改为 `support`，依据是 `I still prioritize safety`。 | **部分修复**：不再声称风险理由改变；但仍把安全优先扩大为高受伤风险理由持续成立，文本没有直接确认该风险判断。 |
| 跳伞：安全承诺及限定词 | 安全优先被标为 `support`，但未绑定模拟限定，旧引文越界。 | 安全承诺仍为 `support`；模拟体验有明确限定，但安全记录也把未关联的 `new-0` 模拟词挂到 `new-8` 的安全主张上。 | **部分修复**：安全支持的方向和三个单独旧单元的首轮短引文得到改善。**新错误**：模拟限定错绑安全主张且来源不属于该记录的关联单元；`For now` 未作为时间限定提取，另有记录遗漏 `u3` 的对应引文。 |

本轮所有主张的 `event_date` 均为 `null`。它不代表限定词完整：例如晋升的 `recently`、转岗的 `now` 和跳伞的 `For now` 在 v2 均未放入各自主张的结构化限定词。
