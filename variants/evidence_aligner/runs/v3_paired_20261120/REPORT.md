# v3 五案配对结果及逐项语义审核

本轮先完成 [v2 离线诊断](../v2_offline_diagnosis_20261120/REPORT.md)，然后以各自保存的 v1/v2 相同输入回放。五案的完整输入、旧单元、新单元、来源文本和发送的 user 消息字节的 SHA-256 均在调用前与两版一致；使用 `qwen-plus-2025-12-01`、temperature 0、JSON 模式、8192 最大输出 token、0 自动重试。实际 **5 次请求、5 次模型响应，每案 1 次**；系统提示词和 schema 为 v3，因此这不是相同提示词实验。

原始响应没有改写。逐案 JSON 保存了原输入、请求、提供方响应、token、原始及解析响应、来源补全与原始校验；冻结代码和提示词在 `frozen_code/`。语义意见由助手在看到 v1/v2 后逐条审核，属于非盲的开发评估，不是独立金标准，人工复核仍然必要。按需求，单独保存 [semantic_audit.json](semantic_audit.json)；由 `review_alignment_v3.py` 生成的 [reviewed_results.json](reviewed_results.json) 将结构错误、语义错误、缺失依据及待判断项分列，不改变原始响应。

## 三类重点错误

### 咨询公司获客与本人身份

- **输入来源**：固定的 `manually_mapped_new.raw_statement` 和 `memory_quotes` 说“我的咨询公司终于获得一些初始客户”，人工属性是 `client_milestone`；所选输入单元没有写本人为创始人或经营者。v2 两条 `new_claim` 分别生成 `user runs ...` 和 `founder/operator`，说明还说是负责人，扩大来自该次模型生成。
- **v3**：不再生成主张改写字段，因而没有再输出明确的 `founder/operator` 身份文字；但 `records[0]` 和 `[1]` 仅引用 `my consulting firm`／`consulting firm`，却把旧雇主和旧职位均标为 `state_change`。新片段不足以证明历史雇主结束、职位被替换或现任职务。这是 v2 已避免而 v3 重新出现的严重语义错误，不能称为身份问题已修复。
- `lately` 实际限定“最近感到宽慰”，v3 却分别放在旧雇主及旧职位变化记录下；虽然锚点引用整段原文、能够定位，其语义作用对象错误。获客事实只出现在限定词的长锚点中，没有作为主要新引用单列；宽慰也未形成单独断言。v2 漏掉的 `unsplit-new-2` 在 v3 被引用，但人脉作用、关系带来机会和维系关系仍合为一条。

### 安全优先与受伤风险理由

v2 将 `I still prioritize safety` 标为支持原先“高受伤风险导致厌恶”的理由，超出直接证据。v3 的 `records[1]` 更进一步将该理由标成 `state_change`，而新引文既未确认该理由继续成立，也未说该理由改变；同一记录的 `missing_evidence` 又称安全优先说明原安全担忧仍起作用，继续把一般安全价值扩大为具体高受伤风险判断。`records[2].missing_evidence` 还称模拟活动与安全承诺不冲突，亦非所选引文直接给出。

可以从原文支持的是“仍重视安全”；是否仍认为真实极限运动受伤风险高、该风险是否仍是厌恶理由，以及模拟活动是否改变安全冲突，均缺少直接依据，需人工判断或补充原文。

### 模拟、时间和否定

- 跳伞 `records[0]` 把 `simulated` 和 `recently` 放在模拟体验的原文锚点内，这是限定词定位上的改善；但该条仍把模拟体验标成真实极限运动态度的 `state_change`，恢复了 v1 的语义错误，而 v2 对此采用 `supplement`。模型的 `missing_evidence` 甚至同时写明无法证明真实态度改变。
- 跳伞 `records[1]`、`[2]` 将 `For now` 的种类写成 `plan` 而非时间，并把整个两句作为锚点，掩盖它主要限定当前享受／观察发展；两条还把肯定持续性的 `still prioritize safety` 标作 `negation`。`didn't expect` 限定过去的预期，不是否定实际享受；v3 没有提取它，也未把体验、意外享受及更愿意尝试分成具体断言。
- 晋升 `recently` 正确绑定晋升，修复 v2 漏项。转岗 `finally` 放在含转岗的锚点内，但锚点也包含平衡改善，`now` 仍漏掉；旧侧 `lately` 引用了其他旧上下文且不在该单元的来源映射中，校验已报错。Susan 的 `lately` 长锚点同时包含思考与认识，需缩至实际修饰的“思考职业”；“现职对福祉的支持不及期望”中的比较性否定未结构化。

## 其他修复、错误与人工判断

- Susan 的支持引文不再混入 Daniel 的句子，避免直接把 Daniel 行为归给 Susan；但 Daniel 的独立主张仍没有记录。`records[2]` 将新求职内容与两个不相关的旧单元关联，却不给旧引文；求职意向及现职支持不足也未拆成两条。新引文没有明确称 Susan 为朋友，是否足以支持旧朋友关系仍需判断；旧记忆本身明确将 ThomasSusan 称作 Susan。
- 晋升记录直接引用升为 lead director 的陈述并正确绑定 `recently`，职位变化有依据；公司写 `no_clear_change` 是保守判断，但新句也可被视为直接支持同一公司。
- 转岗引文支持已完成转岗，不能据此推断以后不再找工作；转岗、宽慰和平衡改善合在一条，`now` 未绑定。错误的旧侧来源已被结构校验拦截。
- 每个实际限定词都会进入 `scope_review`，因为程序只能确定字符串、同侧来源和锚点的字面关系，无法自动验证句法修饰关系或蕴含。程序不依据记录时间推算事件日期。

人工审计记录了 17 条 `judgment=error` 发现，涉及 10 个自定义类型；这些是本次非盲审核的标注条目，并可能描述同一记录的不同侧面，不能与 v2 的结构报错条数直接比较。五案均有语义错误、未决判断或缺失依据，因此均标记 `requires_attention`，不应直接用于下游记忆更新。
