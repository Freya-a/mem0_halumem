# v5 设计：拆分粒度、关系与局部证据范围

依据用户 2026-11-04 的明确执行请求，保留 v4，新增 v5 提示词；完成后对指定五个历史案例各请求一次，不重试。

## 范围与方案选择

选择：沿用 v4 的输入、输出 JSON 和现有 backend/parser/validator，只修改提示词。另建独立实验目录，复制同一输入和历史 v4 响应，程序检查与语义初审分别保存。

其他方案：增加关系字段会要求改解析器，不符合范围；只要求输出更多事实会诱发强拆和关系遗漏，不采用。此选择由执行者依据用户约束作出，不声称用户额外审阅过设计。

## 提示词行为

1. 先在旧记忆内部识别可分别判断、可分别变化的谓词；优先拆分独立的信息，单个谓词的对象特征组合不机械拆词。不预设条数。
2. 在事实正文保留因果、条件、否定、情态、时间及连接词作用范围。允许为保留关系而有必要重叠；不能安全拆开的关系段整体保留。
3. 存在多种合法语法解释时保留原文关系段，并具体记录待确认的连接范围，不自行确定某个因果或时间解释。pending 和引文不能替代正文中的关系。
4. raw 只由旧记忆产生；有依据的上下文消歧只写补充正文并引用相应 context。无时态片段不强行补过去或现在时。
5. supports 按单条引文解释直接内容与限制；不得将相容态度推成活动、将重复推成修辞目的、将助手建议/问句推成用户承诺。一般描述和更强的旧总结存在差异时保留旧命题并记录来源强度待确认。
6. 保留 v4 的强制 memory 逐字引文、ID、连续编号、最小补足、否定和不确定语气规则；不增加字段或现实真伪判断。

## 实验边界

- 新请求仅五个：运动偏好、波斯猫照料、父亲资料、瑜伽、伴侣资料；每个 v5 一次，共最多五次。v4 只复制历史响应，零新请求。
- 使用既有 qwen-plus backend 和项目配置；SDK max_retries=0，HTTP follow_redirects=False；保持历史显式生成参数和 180 秒 timeout。
- 提示词、输入、设计和复核协议在请求前冻结并记录 SHA-256。五例已用于设计，是定向回归观察，不能称独立泛化评估。
- 排他创建批次/单例尝试文件；失败保留原响应和诊断，不补引文、不修 JSON、不标成成功、不再次发送。
- 不修改 parser/validator、默认 DESIGN、Mem0、历史结果；不写知识库，不运行完整开发子集。

## 验证与交付

程序只检查 JSON/schema/ID/连续编号/来源存在/引文逐字匹配，并离线重放原校验器。另逐条检查正文覆盖、拆分粒度、关系、raw 边界、每项 supports 和 pending 一致性，标明“初步判断，待人工确认”。

对比报告逐案例展示旧记忆、输入上下文、v4/v5 原始事实、全部引文与支持说明、待确认项及关系初审；不改模型字段。保存程序摘要、语义初审、调用记录和历史文件完整性核验。
