# v6 真实开发记忆初步验证

## 结论与范围

**v6 目前不宜直接当作语义可靠的拆分器使用。** 8 条既有开发子集记忆各做 1 次真实模型请求；7 条通过现有程序校验，1 条因非逐字引文被拒绝。通过的结果中仍观察到旧命题谓词改变、因果/while 关系丢失等问题；这说明结构通过不等于语义正确。

全部语义判断为本次 AI 初审，待人工确认，不是人工金标准、总体错误率或稳定性估计。样本按覆盖难点定向挑选，来自既有 v3/v4/v5 研究案例，并非随机或独立留出集；不能据此认定 v6 优于或劣于其他版本。只做一次抽样，无法量化同一案例的波动。

## 实验设置

- 样本来自历史已核验来源的 8 条开发子集旧记忆，逐字复用对应 input JSON 和当时 source_context；清单及原始快照位置见 [历史案例目录](../real_mem0_v3_v4_comparison_20261104_once/CASE_CATALOG.md)。没有传入目标会话新证据、人工标签或本次复核意见。
- 使用 `v6_splitter.split_memory_v6`、冻结的 [v6 提示词](frozen_prompt.txt) 和已有 OpenAI-compatible backend；模型配置记录为 `qwen-plus`，生成参数未显式设置，具体模型修订、供应商默认采样及内部行为未知。
- 每条一次客户端请求，SDK 重试关闭，失败不修补、不重试。原始响应和程序状态分别保存在各 case 目录；失败没有 `result.json`。
- [audit.py](audit.py) 离线重放保存的原始 JSON 及输入，核对 v6 冻结提示词和输入哈希，并使用现有校验器重现接受或拒绝；只证明相应结构、身份与逐字来源检查。

## 建议的下一步

优先处理两个问题：① 对可独立拆分的内容，仍要把因果、条件、时间和连接作用范围写进相应事实正文；若不安全则保留关系段；② raw 不能借用上下文中的近义但不同谓词，辅助来源只用于消歧。额外检查 pending 与正文是否自相矛盾，引文不得用省略号拼接。以上是定向诊断建议，不证明单靠增加提示词规则就能解决。

当前 8 条可作为后续改进的回归集。若调整 v6，应另选未参与提示词改动的真实案例，并固定相同输入和验证方案，再与基线比较。保持原始输出、失败及提示词快照可供复核。
